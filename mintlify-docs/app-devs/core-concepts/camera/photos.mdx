<BetaNote />

`session.camera.takePhoto` captures a still on glasses that have a camera, like
Mentra Live. It resolves once the photo is on the phone, as one of your
miniapp's own files. Nothing is uploaded: your miniapp decides where the photo
goes.

```typescript src/background/index.ts
import { registerMiniapp } from "@mentra/miniapp/background";

registerMiniapp((session) => {
  session.input.onButtonPress(async () => {
    if (!session.capabilities?.hasCamera) return;
    const photo = await session.camera.takePhoto();
    const bytes = await session.blob.bytes(photo.key);
    if (!bytes) return; // the photo expired
    await fetch("https://example.com/photos", {
      method: "POST",
      headers: { "Content-Type": photo.mimeType },
      body: bytes,
    });
  });
});
```

Camera needs the `CAMERA` permission and glasses with a camera. Declare a
`CAMERA` permission in your [manifest](/app-devs/core-concepts/miniapp-manifest)
so the call is allowed, and a `CAMERA` hardware requirement so the miniapp only
installs on glasses that can capture. Check `session.capabilities.hasCamera`
before calling so you don't fire a request the glasses can't satisfy.

## Take a photo

`takePhoto` sends the request, waits while the glasses capture and send the
photo to the phone, then resolves with where your miniapp finds it. The photo works
without an internet connection.

```typescript
const photo = await session.camera.takePhoto({ size: "high", sound: false });
// photo.key        – the photo's key in session.blob
// photo.url        – loads in your miniapp's screen, e.g. <img src={photo.url}>
// photo.mimeType   – e.g. "image/jpeg"
// photo.size       – bytes
// photo.expiresAt  – when the phone deletes it (Unix ms), 30 minutes after capture
// photo.thumbnail  – a small copy: { key, url, width, height, mimeType }
```

The default `size`, `"auto"`, is the largest photo that arrives in about 2 seconds on the link it
comes over, which the glasses decide when they send it: 1280×960 at JPEG quality 60 over Bluetooth,
the full sensor (4032×3024) over the glasses Wi-Fi link. A fixed `size` is the same on every link,
and a larger one takes longer over Bluetooth. Glasses from before `auto` take it as `"medium"`.

All options are optional. The defaults are listed below.

| Option | Type | Default | What it does |
|---|---|---|---|
| `size` | `"auto" \| "low" \| "medium" \| "high" \| "max"` | `"auto"` | Resolution: `auto` by link, as above, or a fixed one. |
| `compress` | `"none" \| "low" \| "medium" \| "high"` | `"none"` | JPEG compression applied on the glasses. |
| `sound` | `boolean` | `true` | Play a shutter sound on the glasses. |
| `saveToGallery` | `boolean` | `false` | Keep a copy in the glasses gallery. |
| `exposureTimeNs` | `number` | auto | Manual shutter time in nanoseconds. Honored only on cameras with manual exposure; ignored otherwise. Omit to auto-expose. |

The result is a `PhotoTaken`:

| Field | Type | Description |
|---|---|---|
| `requestId` | `string` | Correlates the request with glasses status and phone logs. |
| `key` | `string` | The photo's key in [`session.blob`](/app-devs/core-concepts/blob). |
| `url` | `string \| undefined` | A URL your miniapp's own screen can load until the photo is deleted. |
| `mimeType` | `string` | MIME type of the image, e.g. `"image/jpeg"`. |
| `size` | `number` | Image size in bytes. |
| `expiresAt` | `number` | When the phone deletes the photo, as a Unix time in milliseconds. |
| `thumbnail` | `PhotoThumbnail \| undefined` | A small copy of the photo, made on the phone (below). Absent if the photo couldn't be read as an image. |

### Thumbnails

A full photo decodes to tens of megabytes on a screen, so a list or timeline of photos should
show their thumbnails. The phone makes one for every photo as it arrives: a JPEG at most 512 px on
its long side, upright, about 20 to 40 KB. It is one of your miniapp's own files like the photo,
under its own `key` in `session.blob`, and it is deleted with the photo.

```tsx
<img src={photo.thumbnail?.url ?? photo.url} width={photo.thumbnail?.width} loading="lazy" />
```

| Field | Type | Description |
|---|---|---|
| `key` | `string` | The thumbnail's key in `session.blob`. To keep it past the photo, store a copy under a key of your own. |
| `url` | `string \| undefined` | A URL your miniapp's own screen can load until the photo is deleted. |
| `width`, `height` | `number` | Its size in pixels. |
| `mimeType` | `string` | `"image/jpeg"`. |

A thumbnail exists once the full photo is on the phone. To show something sooner, ask the
glasses for a preview (`preview: true`, below), which comes over Bluetooth before the full photo.

## Take photos in stages

`capture` returns at once with the photo's stages. Use it to take photos back to
back and fetch only the ones you keep: the full photo waits on the glasses until
you ask for it. With `preview: true` the glasses also send a small preview right
after the capture, which you can show before the full photo comes; without it
they send none, and the capture has no `preview`.

```typescript
const capture = session.camera.capture({ size: "high", preview: true });
await capture.captured;                      // the camera is free for the next photo
const preview = await capture.preview;       // { url, width, height }, at most 500 px
const photo = await capture.photo();         // the full photo, as takePhoto gives it
await capture.release();                     // or skip photo(): the glasses delete it
```

Photos are never refused because others are being sent; only a capture
requested while another is being taken rejects with `CAMERA_BUSY`. `preview.url`
is a `data:image/jpeg;base64,` URL. The full photo stays on the glasses for 30
minutes at most; `photo()` asks for it the first time and returns the same photo
after that. For a preview only, await `preview` and `release()` without calling
`photo()`. `takePhoto(options)` is `capture(options).photo()` with no preview,
releasing the glasses' copy once the photo is on the phone.

### Camera sessions

A miniapp that takes many photos, like documenting a site, opens the camera for
the whole stretch of work instead of calling `capture()` on its own:

```typescript
const camera = session.camera.open({ size: "medium" });

// A tap: one photo, in the session's turn, with its shutter sound.
const tap = await camera.capture({ sound: true });

// Or photos back to back on their own, silently.
const run = camera.continuous({ sound: false });
run.onPhoto((capture) => {        // a normal capture: captured, photo(), release()
  void capture.photo().then((photo) => show(photo.url)).finally(() => capture.release());
});
await run.stop();                 // the session stays open

await camera.close();             // or close the miniapp
```

From `open()` to `close()` the Mentra App holds the glasses Wi-Fi link, so full
photos come over it, and keeps the camera warm with the session's settings, so
each photo is taken at once. Every photo goes through the session the same way,
one at a time: the next starts once the camera took the previous one. Only what
asks for a photo differs: `capture(options)` for a tap, with its options over
the session's, or `continuous(options)`, which takes photos on its own as fast
as the camera takes them. It waits by itself while the link is down, so photos
never pile up on the glasses behind Bluetooth. `close()` stops taking photos at
once and resolves once the photos the session handed out are released; closing
the miniapp closes it. It requires CAMERA permission.

### Keep the camera warm

Opening the camera takes about a second. A miniapp that takes photos on demand
for a while, like a session that photographs on each button press, can keep it
open:

```typescript
const warm = await session.camera.warmUp({ size: "medium" }); // resolves once the camera is warm
// ... capture({ size: "medium" }) and takePhoto({ size: "medium" }) start at once
await warm.release();                                           // or close the miniapp
```

Warm with the same `size`, `mode`, `exposureTimeNs`, `zsl` and `mfnr` as your
photos: a photo with other settings reconfigures the camera. The phone keeps the
camera warm until you release it, however long. A miniapp holds one warm-up at a
time; a new `warmUp()` replaces the previous one.

## Use the photo

The photo is an ordinary `session.blob` entry that the phone deletes after 30
minutes. It doesn't count toward your miniapp's storage limit.

- **Send it somewhere.** Read the bytes in your background script and upload
  them yourself: `await session.blob.bytes(photo.key)`.
- **Show it.** Pass `photo.url` to your screen and use it as an image source.
  The URL loads only in your miniapp's own screen, in development as once
  installed.
- **Share it.** `await session.blob.share(photo.key)` opens the share sheet.
- **Keep it.** Store a copy under a key of your own before it expires:
  `await session.blob.set("saved/" + photo.requestId, bytes)`.

### Updating from uploaded photos

`takePhoto` used to upload the photo to Mentra's cloud and return a `photoUrl`.
It now needs Mentra App 3.5.0 or later, so set `"minHostVersion": "3.5.0"` in
your [manifest](/app-devs/core-concepts/miniapp-manifest). On an older Mentra
App the call rejects and asks the user to update. Replace reads of `photoUrl`
with `photo.url` on screen, or the bytes from `session.blob` everywhere else.
The `transferMethod` option is gone: a photo for the phone always comes over
Bluetooth.

## Photos during a stream

While the glasses stream video, their camera can't also take a photo. When the
stream passes through the phone (a Teams call in Mentra Call, or a managed
stream started with `ingest: "whip"`), `takePhoto()` returns the stream's next
video frame instead. The stream doesn't pause, and any miniapp can do this, not
only the one that started the stream.

The frame differs from a camera photo:

- It has the stream's resolution and exposure (720p for a Teams call). `size`,
  `mode`, `compress` and the exposure options don't apply.
- The glasses play no shutter sound and save nothing to their gallery.
- `warmUp()` returns at once: the camera is already open.

Any other stream (SRT, RTMP, or a `direct` stream, which the glasses send
straight to the internet) still rejects `takePhoto()` with `CAMERA_BUSY`.

## Field of view

`setFov` applies a temporary FOV/ROI override owned by the calling miniapp and
resolves after the ASG client reports it was applied. It applies to all captures
(photos and video) while that miniapp is active. When the miniapp closes, the host
restores the previous live miniapp override or the persistent base setting. The
factory/missing base is the centered `standard` preset (102 degrees); existing
saved user values are preserved.

```typescript
// A named preset. The simplest option, always center ROI.
await session.camera.setFov({ preset: "wide" });

// Or an explicit horizontal FOV with a region.
await session.camera.setFov({ fov: 102, roiPosition: "bottom" });
```

The argument is one of two shapes:

| Field | Type | Notes |
|---|---|---|
| `preset` | `"narrow" \| "standard" \| "wide"` | Named preset. Uses center ROI. Mutually exclusive with `fov`/`roiPosition`. |
| `fov` | `number` | Horizontal FOV in degrees. Pair with `roiPosition`. |
| `roiPosition` | `"center" \| "bottom" \| "top"` | Region position for the `fov` form. Defaults to `"center"`. |

It resolves with a `CameraFovResult`:

| Field | Type | Description |
|---|---|---|
| `requestId` | `string` | Correlates the request with ASG logs. |
| `fov` | `number` | The applied horizontal FOV in degrees. |
| `roiPosition` | `"center" \| "bottom" \| "top"` | The applied region position. |
| `timestamp` | `number` | When the setting was applied. |

## Errors

Every method returns a promise that rejects with `{ code, message }` on failure.
Wrap calls in `try`/`catch` and read `code`.

| Code | When |
|---|---|
| `PERMISSION_NOT_DECLARED` | The miniapp didn't declare the `CAMERA` permission. |
| `REQUEST_ABORTED` | The request timed out, or the session was torn down before it completed. |
| `CAMERA_BUSY` | The glasses are streaming in a way the phone can't take a frame from, or another photo is in progress. See [Photos during a stream](#photos-during-a-stream). |
| `INTERNAL` | The phone-side handler threw. The glasses have no camera, capture or transfer failed, or another device error occurred. Read `message`. |

```typescript
try {
  const photo = await session.camera.takePhoto();
  session.ui.send("photo", { url: photo.url });
} catch (err) {
  if (err.code === "PERMISSION_NOT_DECLARED") {
    session.display.render([
      {type: "text", id: "msg", box: {x: 0, y: 0, w: 576, h: 288}, text: "Camera permission not granted"},
    ]);
  }
}
```

### Breaking change: photo compression

Photo compression now accepts exactly `none`, `low`, `medium`, and `high`, sent
unchanged across the Mentra Miniapp SDK, Bluetooth SDKs, and glasses.
The default is `none` everywhere. Glasses encode these as JPEG Q95, Q88, Q78,
and Q60 respectively; `size` controls dimensions separately. `none` still uses
lossy JPEG encoding. Unknown values are rejected.

Photo compression is handled by the phone and glasses.

The former `heavy` spelling is removed; callers must use `high`. Android's native
default changes from `medium` to `none`. Existing miniapps may therefore produce
different JPEG quality or payload sizes. There are no compatibility aliases or wire translations.
