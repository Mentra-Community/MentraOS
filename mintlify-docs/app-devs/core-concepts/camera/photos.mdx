`session.camera.takePhoto` captures a still on glasses that have a camera, like
Mentra Live. It resolves once the photo is on the phone, as one of your
miniapp's own files. Nothing is uploaded: your miniapp decides where the photo
goes.

```typescript src/background/index.ts
import { registerMiniapp } from "@mentra/miniapp/background";

registerMiniapp((session) => {
  session.input.onButtonPress(async () => {
    if (!session.capabilities?.hasCamera) return;
    const photo = await session.camera.takePhoto();
    const bytes = await session.blob.bytes(photo.key);
    if (!bytes) return; // the photo expired
    await fetch("https://example.com/photos", {
      method: "POST",
      headers: { "Content-Type": photo.mimeType },
      body: bytes,
    });
  });
});
```

Camera needs the `CAMERA` permission and glasses with a camera. Declare a
`CAMERA` permission in your [manifest](/app-devs/core-concepts/miniapp-manifest)
so the call is allowed, and a `CAMERA` hardware requirement so the miniapp only
installs on glasses that can capture. Check `session.capabilities.hasCamera`
before calling so you don't fire a request the glasses can't satisfy.

## Take a photo

`takePhoto` sends the request, waits while the glasses capture and send the
photo to the phone over Bluetooth, then resolves with where your miniapp finds
it. The photo works without an internet connection.

```typescript
const photo = await session.camera.takePhoto({ size: "high", sound: false });
// photo.key        – the photo's key in session.blob
// photo.url        – loads in your miniapp's screen, e.g. <img src={photo.url}>
// photo.mimeType   – e.g. "image/jpeg"
// photo.size       – bytes
// photo.expiresAt  – when the phone deletes it (Unix ms), 30 minutes after capture
```

A larger `size` takes longer to arrive: Bluetooth carries the whole photo.

All options are optional. The defaults are listed below.

| Option | Type | Default | What it does |
|---|---|---|---|
| `size` | `"low" \| "medium" \| "high" \| "max"` | `"medium"` | Capture resolution. |
| `compress` | `"none" \| "low" \| "medium" \| "high"` | `"none"` | JPEG compression applied on the glasses. |
| `sound` | `boolean` | `true` | Play a shutter sound on the glasses. |
| `saveToGallery` | `boolean` | `false` | Keep a copy in the glasses gallery. |
| `exposureTimeNs` | `number` | auto | Manual shutter time in nanoseconds. Honored only on cameras with manual exposure; ignored otherwise. Omit to auto-expose. |

The result is a `PhotoTaken`:

| Field | Type | Description |
|---|---|---|
| `requestId` | `string` | Correlates the request with glasses status and phone logs. |
| `key` | `string` | The photo's key in [`session.blob`](/app-devs/core-concepts/blob). |
| `url` | `string \| undefined` | A URL your miniapp's own screen can load until the photo is deleted. |
| `mimeType` | `string` | MIME type of the image, e.g. `"image/jpeg"`. |
| `size` | `number` | Image size in bytes. |
| `expiresAt` | `number` | When the phone deletes the photo, as a Unix time in milliseconds. |

## Use the photo

The photo is an ordinary `session.blob` entry that the phone deletes after 30
minutes. It doesn't count toward your miniapp's storage limit.

- **Send it somewhere.** Read the bytes in your background script and upload
  them yourself: `await session.blob.bytes(photo.key)`.
- **Show it.** Pass `photo.url` to your screen and use it as an image source.
  The URL loads only in your miniapp's own screen. It is absent when your screen
  loads from a development server and the photo is larger than 1 MB; read the
  bytes there.
- **Share it.** `await session.blob.share(photo.key)` opens the share sheet.
- **Keep it.** Store a copy under a key of your own before it expires:
  `await session.blob.set("saved/" + photo.requestId, bytes)`.

### Updating from uploaded photos

`takePhoto` used to upload the photo to Mentra's cloud and return a `photoUrl`.
It now needs Mentra App 3.5.0 or later, so set `"minHostVersion": "3.5.0"` in
your [manifest](/app-devs/core-concepts/miniapp-manifest). On an older Mentra
App the call rejects and asks the user to update. Replace reads of `photoUrl`
with `photo.url` on screen, or the bytes from `session.blob` everywhere else.
The `transferMethod` option is gone: a photo for the phone always comes over
Bluetooth.

## Field of view

`setFov` applies a temporary FOV/ROI override owned by the calling miniapp and
resolves after the ASG client reports it was applied. It applies to all captures
(photos and video) while that miniapp is active. When the miniapp closes, the host
restores the previous live miniapp override or the persistent base setting. The
factory/missing base is the centered `standard` preset (102 degrees); existing
saved user values are preserved.

```typescript
// A named preset. The simplest option, always center ROI.
await session.camera.setFov({ preset: "wide" });

// Or an explicit horizontal FOV with a region.
await session.camera.setFov({ fov: 102, roiPosition: "bottom" });
```

The argument is one of two shapes:

| Field | Type | Notes |
|---|---|---|
| `preset` | `"narrow" \| "standard" \| "wide"` | Named preset. Uses center ROI. Mutually exclusive with `fov`/`roiPosition`. |
| `fov` | `number` | Horizontal FOV in degrees. Pair with `roiPosition`. |
| `roiPosition` | `"center" \| "bottom" \| "top"` | Region position for the `fov` form. Defaults to `"center"`. |

It resolves with a `CameraFovResult`:

| Field | Type | Description |
|---|---|---|
| `requestId` | `string` | Correlates the request with ASG logs. |
| `fov` | `number` | The applied horizontal FOV in degrees. |
| `roiPosition` | `"center" \| "bottom" \| "top"` | The applied region position. |
| `timestamp` | `number` | When the setting was applied. |

## Errors

Every method returns a promise that rejects with `{ code, message }` on failure.
Wrap calls in `try`/`catch` and read `code`.

| Code | When |
|---|---|
| `PERMISSION_NOT_DECLARED` | The miniapp didn't declare the `CAMERA` permission. |
| `REQUEST_ABORTED` | The request timed out, or the session was torn down before it completed. |
| `INTERNAL` | The phone-side handler threw. The glasses have no camera, capture or transfer failed, or another device error occurred. Read `message`. |

```typescript
try {
  const photo = await session.camera.takePhoto();
  session.ui.send("photo", { url: photo.url });
} catch (err) {
  if (err.code === "PERMISSION_NOT_DECLARED") {
    session.display.render([
      {type: "text", id: "msg", box: {x: 0, y: 0, w: 576, h: 288}, text: "Camera permission not granted"},
    ]);
  }
}
```

### Breaking change: photo compression

Photo compression now accepts exactly `none`, `low`, `medium`, and `high`, sent
unchanged across the Mentra Miniapp SDK, Bluetooth SDKs, and glasses.
The default is `none` everywhere. Glasses encode these as JPEG Q95, Q88, Q78,
and Q60 respectively; `size` controls dimensions separately. `none` still uses
lossy JPEG encoding. Unknown values are rejected.

Photo compression is handled by the phone and glasses.

The former `heavy` spelling is removed; callers must use `high`. Android's native
default changes from `medium` to `none`. Existing miniapps may therefore produce
different JPEG quality or payload sizes. There are no compatibility aliases or wire translations.
