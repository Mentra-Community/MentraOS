`session.transcription` turns what the user says into text. Register a handler and
you start getting results; the SDK handles the subscription for you.

```typescript
session.transcription.on((data) => {
  if (data.isFinal) {
    session.display.render([{type: "text", id: "msg", box: {x: 0, y: 0, w: 576, h: 288}, text: data.text}]);
  }
});
```

Transcription needs the `MICROPHONE` permission in your
[manifest](/app-devs/core-concepts/miniapp-manifest). Without it, the phone
rejects the subscription with `PERMISSION_NOT_DECLARED` and no events arrive.

## Results

Each event is a `TranscriptionData`:

| Field | Type | Notes |
|---|---|---|
| `text` | `string` | The transcribed text so far. |
| `isFinal` | `boolean` | `false` for interim results that keep updating, `true` once the utterance is settled. |
| `language` | `string?` | The detected language (when auto-detecting). |

Interim results stream as the user speaks and get replaced; wait for `isFinal` if
you only want settled text.

## Targeting languages

`on()` auto-detects the language. To listen for specific ones, use
`forLanguage()` with BCP-47 tags:

```typescript
// One language.
session.transcription.forLanguage("en-US", (data) => { /* … */ });

// Several at once.
session.transcription.forLanguage(["en-US", "es-ES"], (data) => { /* … */ });
```

Each call is independent, and you can have several active at the same time.

## Requiring on-device transcription

Pass `{forceLocal: true}` as the final argument to route that subscription
through on-device STT and suppress cloud transcript delivery:

```typescript
session.transcription.on(handler, {forceLocal: true});
session.transcription.forLanguage("en-US", handler, {forceLocal: true});
```

Cloud transcripts are suppressed for the local-only subscription, even while
other miniapps continue using cloud transcription. Routing is per listener, so
a default listener on the same stream can continue receiving cloud
transcription.

The phone runs one on-device speech model at a time, the one the user picked
on its Speech page, and every miniapp's on-device transcription uses it. If it
isn't downloaded yet, the phone downloads it when your subscription arrives.
Subscribe with `on()` to get text in whatever language that model is; a
`forLanguage()` subscription in a different language gets no on-device text.
The model stays loaded while any miniapp keeps an on-device subscription open.

### Model status

`onModelStatus` tells you what the on-device model behind your subscriptions
is doing. You get the current state right away, then every change:

```typescript
session.transcription.onModelStatus((status) => {
  if (status.state === "downloading") showHint(`Downloading speech model… ${status.progress ?? 0}%`);
  if (status.state === "ready") showHint("Listening");
  if (status.state === "unavailable") showHint(status.reason ?? "On-device speech is unavailable");
});
```

| Field      | Type                                                      | Notes                                       |
| ---------- | --------------------------------------------------------- | ------------------------------------------- |
| `language` | `string`                                                  | BCP-47 language of the picked model.        |
| `state`    | `"downloading" \| "loading" \| "ready" \| "unavailable"` | `ready` means on-device text is flowing.    |
| `progress` | `number?`                                                 | `0`–`100` while downloading.                |
| `reason`   | `string?`                                                 | Why the model is unavailable, when it is. |

The state is `unavailable` when you have no on-device subscription, when the
download or load failed (the phone retries on its own), or when every
on-device subscription asks for a language other than the picked model's
(`reason` names the picked language).

### Ending an utterance early

A recognizer ends a line after its own end-of-speech pause. When your own rule
decides the user is done, for example after
[voice activity](/app-devs/core-concepts/microphone/audio-chunks#voice-activity)
reports enough silence, end the line now:

```typescript
const finalText = await session.transcription.finishUtterance();
```

It resolves with the line's final text after that final transcript has reached
your handlers, `""` when nothing was pending, or `null` when no on-device
recognizer is running or the picked model can't end a line early (models that
transcribe in fixed chunks deliver their final text on their own).

<Warning>
  `finishUtterance()` needs an active `{forceLocal: true}` subscription and only affects on-device transcription. The
  phone runs one recognizer for every miniapp, so it ends the current line for every on-device subscriber, Captions
  included.
</Warning>

## Configuring

`configure()` tunes the recognizer. It's fire-and-forget and applies to
subsequent results:

```typescript
session.transcription.configure({
  languageHints: ["en", "ja"],     // ISO 639-1 hints to improve detection
  vocabulary: ["MentraOS", "HIPAA"], // boost domain terms
  diarization: true,                // tag speakers when the provider supports it
});
```

## Cleaning up

Every subscription returns an unsubscribe function. `stop()` tears down every
subscription this module owns at once:

```typescript
const off = session.transcription.on(handler);
off();                       // drop this one

session.transcription.stop(); // drop all of them
```

`session.transcription.hasPermission` tells you whether `MICROPHONE` is declared
in your manifest. It does not tell you whether the user granted the OS prompt: if
they denied it, your handler simply never fires. See
[Permissions](/app-devs/core-concepts/permissions).

<Note>
Transcription is for text. For raw audio frames or voice-activity detection, use
[`session.mic`](/app-devs/core-concepts/microphone/audio-chunks). For translated
text, use [`session.translation`](/app-devs/core-concepts/translation). Subscribing
to one does not subscribe you to the others.
</Note>
