# PR CI: goals and current design

## Requirements: the outcomes we want

1. **Verify that the candidate software compiles in the least time possible.**
   Give developers trustworthy feedback quickly. Repeating work that has already
   established compilation of the same inputs adds latency without adding confidence.
2. **Make the complete candidate software easy to install and test from
   `#pr-builds` on Android, iPhone and Mac.** Testers should quickly get from the
   post to using the PR's mobile app and corresponding glasses software. Clear
   status and software identity must let them tell what is ready and what they
   are testing. Glasses OTA must be enabled for this to be a complete installation.

These are the goals. Caching mechanisms, artifact formats, signing steps,
installer tools and Slack layout are design choices that can change to serve
them better. The present Mac installation experience has substantial friction;
its implementation is not the desired end state.

## Current specification

Use this common flow for Android mobile, iOS mobile and the ASG client:

1. Identify the compilation inputs for the PR candidate.
2. Reuse a verified matching compiled artifact when those inputs have not
   changed. Compile only when no usable match exists.
3. Prepare the candidate's configuration and installable outputs. A cache hit
   must not carry another PR's OTA target or misleading version identity.
4. Verify the delivered software and publish its installation links and status
   to `#pr-builds`.

The current artifact-reuse design fingerprints sources, dependencies, relevant
build configuration and tools. PR identifiers, OTA URLs and packaging build
numbers belong in packaged configuration so changing them does not cause an
otherwise unnecessary compilation. Verify cached artifact integrity and
provenance before accepting it as compilation evidence.

Android and iOS should share this model, configuration contract, publication
rules and reporting wherever practical. Keep platform-specific work at the
native compilation, signing and installation boundaries. One iOS compilation
serves both iPhone and Mac.

The current delivery routes are an Android APK, a signed ad hoc iPhone IPA with
a direct installation link, and a Mac ZIP with an installer. The mobile apps
select the same per-PR glasses OTA manifest, whose ASG client is also reused
when its compilation inputs match. These choices are open to improvement.

## Gaps being closed in PR #4125

- At the start of this work, Android and ASG had compiled-artifact reuse; iOS had only build
  caches and performed a new archive. Build caches alone do not satisfy
  the reuse specification.
- The installable iOS/Mac path omitted the PR OTA configuration. The first
  iteration of PR #4125 supplies it through the build environment, but must
  move that per-PR value to packaged configuration to support artifact reuse.
- Mac installation works but requires too much setup and interaction. Improving
  that experience remains part of the installation goal.
- Intermittent iOS signing failures can prevent delivery even after compilation.
  Rebuilding source is not a remedy for a signing-only failure; retain usable
  compilation outputs and make recovery target the failed stage.

## Evidence of success

- A changed-input run establishes compilation and publishes installable outputs.
- An unchanged-input run skips mobile/ASG compilation and still publishes the
  correct candidate configuration. This applies equally to Android and iOS.
- Record time to compilation verdict and time to ready-to-test publication for
  both cases, identifying where time is spent rather than assuming a cache hit
  makes the whole pipeline fast.
- The exact downloads install and launch on Android, iPhone and Mac, and their
  effective OTA configuration selects the corresponding glasses software.
- A missing, corrupt or incompatible artifact leads to a fresh build; a failed
  publication never becomes a misleading ready-to-test post.
