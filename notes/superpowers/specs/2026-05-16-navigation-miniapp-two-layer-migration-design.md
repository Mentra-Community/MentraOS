# Navigation Mini App — Two-Layer Migration & SDK RPC Helper

## Why

Two reasons stacked into one piece of work:

1. **Navigation is still on the old single-bundle architecture.** Everything (MiniappSession, glasses subscriptions, React UI) runs in the WebView. Close the WebView mid-trip and the glasses go silent — the wrong shape for an always-on service. The new two-layer architecture (background JSContext + UI WebView) fixes this; `sdk/example-miniapp/` is the reference implementation.

2. **Two-layer apps need request/response across the bridge, and the SDK doesn't expose it.** `session.ui` is fire-and-forget by design — `mobile/modules/miniapp/src/modules/ui.ts` says so explicitly: "Authors who need request/response semantics implement it themselves using two channels." That decision was provisional (the SDK author was moving fast). Navigation will need RPC heavily (`computeRoute`, Places autocomplete, storage reads), and any non-trivial future mini app will too. If we let each mini app roll its own helper, the contract fragments.

This spec covers both: add RPC to the SDK first, then migrate Navigation. All in `mentra-miniapp-sdk-2`.

## What changes

### Part 1 — SDK RPC helper

A new request/response surface on the existing `session.ui` / `mentra` bus:

- `mentra.request(channel, payload, options?)` — UI → background call returning a Promise
- `session.ui.handle(channel, handler)` — background-side handler registration
- `useRpc(channel)` — React hook bundling abort-on-unmount + abort-previous-call
- A single `Channels` registry with `Rpc<Req, Res>` branding to distinguish RPC channels from broadcast channels — static type-check prevents using the wrong API on the wrong channel.
- Wire format: optional `requestId` added to the envelope (no payload pollution); new `UI_CANCEL` envelope type for `AbortSignal` propagation.

### Part 2 — Navigation migration

Split the existing single-bundle app into:
- **Background** (`src/background/`): `NavigationController` owns `MiniappSession`, all glasses subscriptions, trip state, the HUD logic, storage, Places REST, navigation manager.
- **UI** (`src/ui/`): Pure React/DOM. Reads channel-pushed state from a Zustand store. Sends user actions via `mentra.send` / `mentra.request`. Hosts Google Maps JS API (the one thing that genuinely needs DOM).
- **Shared** (`src/shared/`): One typed `Channels` registry.

`build.ts` becomes two-output (matches `sdk/example-miniapp/`). `miniapp.json` adds `type: "standard"` and `entry: {background, ui}`.

## Architecture

### Wire protocol changes

Today the envelope carries `{type, channel, payload, seq}`. We add:

- `requestId?: string` — optional envelope-level field. Routers (`MentraUIRouter`, `mentraUiShim`) pass it through unchanged. The SDK helper layer interprets it.
- `UI_CANCEL` — new envelope type, payload-less, carries only `requestId`. Generated by the helper when a caller's `AbortSignal` fires.

Locations to update (~8 small edits, all inside `mobile/`):

1. `mobile/modules/miniapp/src/modules/ui.ts` — extend `UISendEnvelope`, `UIInboundEnvelope` with optional `requestId`; add `UI_CANCEL` to the inbound union.
2. `mobile/modules/engine/src/services/mentraUiShim.ts` — include `requestId` in outbound `msg` frames; preserve it on `recv`; handle `cancel` frame.
3. `mobile/modules/engine/src/services/MentraUIRouter.ts` — pass `requestId` through `routeFromWebView` + `routeFromBackground`; route `cancel` frames in both directions.

The change is invisible to mini app authors. Non-RPC traffic continues unchanged.

### Type system: single registry with `Rpc<>` branding

The SDK exports a branded type:

```ts
// In @mentra/miniapp/ui (and re-exported from /background)
declare const __rpc_brand: unique symbol
export type Rpc<Req, Res> = {[__rpc_brand]: true; req: Req; res: Res}
```

Mini apps declare one registry. Channels wrapped in `Rpc<Req, Res>` are RPC; everything else is broadcast:

```ts
// shared/channels.ts (per-miniapp)
import type {Rpc} from "@mentra/miniapp/ui"
import type {ComputeRouteOptions, ComputeRouteResult} from "@mentra/miniapp"

export interface Channels {
  // Broadcasts (either direction)
  "nav:coords": {lat: number; lng: number; accuracy?: number}
  "nav:trip-state": {status: "idle"|"navigating"|"rerouting"|"arrived"; ...}
  "nav:set-destination": PlaceDetails | null

  // RPC (UI → background)
  "nav:compute-route": Rpc<ComputeRouteOptions, ComputeRouteResult>
  "places:autocomplete": Rpc<{query: string; near?: LatLng}, PlaceSuggestion[]>
  "storage:list-saved": Rpc<void, SavedPlace[]>
  "storage:add-saved": Rpc<SavedPlace, void>
}
```

Static enforcement, in pseudocode:

```ts
type IsRpc<T> = T extends Rpc<any, any> ? true : false
type RpcReq<T> = T extends Rpc<infer Req, any> ? Req : never
type RpcRes<T> = T extends Rpc<any, infer Res> ? Res : never

// mentra.request only accepts RPC channels
request<C extends keyof Channels & string>(
  channel: IsRpc<Channels[C]> extends true ? C : never,
  payload: RpcReq<Channels[C]>,
  options?: {signal?: AbortSignal; timeout?: number},
): Promise<RpcRes<Channels[C]>>

// mentra.send only accepts non-RPC channels
send<C extends keyof Channels & string>(
  channel: IsRpc<Channels[C]> extends true ? never : C,
  payload: Channels[C],
): void
```

A developer who calls `mentra.send("nav:compute-route", ...)` gets a TypeScript error pointing at the channel name (assigned to `never`). Same for `mentra.request("nav:coords", ...)`. Wrong API for the channel is a compile-time error.

### Public API

**UI side (`@mentra/miniapp/ui`):**

```ts
mentra.send(channel, payload)          // existing, broadcast-only after this change
mentra.on(channel, handler)            // existing, returns unsubscribe
mentra.request<C>(
  channel: C,
  payload: RpcReq<Channels[C]>,
  options?: {signal?: AbortSignal; timeout?: number},
): Promise<RpcRes<Channels[C]>>
```

No default timeout. Optional `timeout` per call. Optional `signal` for cancellation. On abort, the helper sends `UI_CANCEL`, removes its listener, rejects with `AbortError` (DOM-standard). On timeout, sends `UI_CANCEL`, rejects with a timeout error. On reply, resolves with the result or throws an `Error` whose `name === "MentraRpcError"` and whose `cause?.code` is set if the handler attached one.

**React hook (`@mentra/miniapp/react`, re-exported from `/ui`):**

```ts
function useRpc<C extends keyof Channels & string>(channel: C): {
  (payload: RpcReq<Channels[C]>, options?: {signal?: AbortSignal; timeout?: number}): Promise<RpcRes<Channels[C]>>
  abort(): void
}
```

The returned callable:
- Has an internal `AbortController` bound to component lifecycle. On unmount, all in-flight calls abort.
- Has an `.abort()` method that aborts the current in-flight call. Useful for keystroke-debounce-cancel patterns (per-keystroke autocomplete).
- Is stable across renders (memoized), so it's safe in `useEffect` deps.
- The caller-provided `signal` is merged with the internal one (via `AbortSignal.any` where available; manual fan-out fallback).

**Background side (`@mentra/miniapp/background`):**

```ts
session.ui.send(channel, payload)         // existing
session.ui.on(channel, handler)           // existing
session.ui.handle<C extends keyof Channels & string>(
  channel: C,                              // must be an Rpc<...> channel (compile-checked)
  handler: (
    payload: RpcReq<Channels[C]>,
    ctx?: {signal: AbortSignal},
  ) => Promise<RpcRes<Channels[C]>> | RpcRes<Channels[C]>,
): () => void  // unhandle
```

- One handler per channel. Registering twice throws synchronously. Returns a deregister function the controller stores like other unsubs.
- The `ctx` parameter is the second positional arg. Handlers that don't care about cancellation use `(payload) => ...`; handlers that do use `(payload, {signal}) => ...`. Both type-check.
- If a `UI_CANCEL` frame arrives with the matching `requestId`, the helper aborts `ctx.signal`. Handlers that respect the signal short-circuit; handlers that don't keep running but their eventual reply is dropped by the helper.
- If the handler throws, the helper sends `{ok: false, error: {message, code?}}` back; the UI's `request` rejects with an Error matching that.
- If the handler returns, the helper sends `{ok: true, result}` back; the UI's `request` resolves.

### Error model

Plain `Error` instances on both sides. No custom error class.

- `err.message` — always set
- `err.name === "MentraRpcError"` — sentinel for "this came from across the bridge"
- `err.cause` — `{code?: string}` if the handler set one (handlers throw `Object.assign(new Error("..."), {cause: {code: "..."}})` or just `new Error("...")`)
- `AbortError` for caller-cancelled requests (matches `fetch` and the DOM)
- A timeout error with `err.name === "MentraRpcTimeoutError"` for timeouts

### What we are NOT building

Listed explicitly so future contributors don't re-litigate:

- **Streaming RPC** (`mentra.subscribe` that pushes multiple values). Streams are channels; "start observing" is a one-shot RPC, background runs the subscription, pushes via `mentra.send`. This is the established pattern in the example.
- **Bidirectional RPC** (background calling into UI). Background → UI is push-only. Cases where background needs UI input (rare) are modeled as a broadcast + fire-and-forget reply channel.
- **Custom error classes** (`class MentraRpcError extends Error`). Sentinel via `err.name`.
- **Default timeouts.** Hides dead-session bugs. Authors who want a deadline pass `{timeout}`.
- **Method-namespace API** (`mentra.rpc.computeRoute({})`). Channel-name-based is honest about the wire.
- **Multiple handlers per channel.** RPC channels have one owner.
- **Replay of buffered requests** beyond the existing `send`-before-`ready` buffering. `request` reuses the same buffer; nothing extra.
- **`@mentra/miniapp/rpc` sub-path.** RPC is part of the main `/ui` and `/background` surfaces. Sub-path would just be ceremony.

### What lives in background

- `MiniappSession` instance
- All `session.location.onUpdate`, `session.heading.onUpdate`, `session.navigation.onUpdate/onRoute/onPivot`, `session.input.*` subscriptions
- Trip state: `running`, `status`, `maneuver`, `routePoints`, `activeDestination`, `activeDestinationName`, `log`, simulator settings
- Glasses HUD logic — the big `useEffect` from `NavigationPage.tsx:240-309` moves here as a controller method that re-runs whenever trip-relevant state changes
- Storage (`session.storage` reads/writes for saved places, recent searches) via `SimpleStorageManager`
- Places REST API (currently in `client/lib/places/places.ts` — pure `fetch`, moves unchanged)
- Compass throttling (~10Hz) — moves with `CompassManager`
- Mid-trip hydration on `ui.onOpen` — controller broadcasts a `nav:snapshot` so a freshly-opened WebView sees current state immediately

### What lives in UI

- React tree, pages, components, router (existing `router.tsx` stays)
- `GoogleMapsManager` (loads `window.google.maps` — DOM-only)
- Map rendering, marker placement, polyline draw, pivot rendering
- Reads everything via channel-fed Zustand store
- Sends user actions via `mentra.send` or `mentra.request`

### NavigationController (sketch)

```ts

import {LocationManager} from "./managers/LocationManager"
import {CompassManager} from "./managers/CompassManager"
import {DisplayManager} from "./managers/DisplayManager"
import {NavigationManager} from "./managers/NavigationManager"
import {SimpleStorageManager} from "./managers/SimpleStorageManager"
import {PlacesManager} from "./managers/PlacesManager"

import type {Channels} from "../shared/channels"

registerMiniapp((session) => new NavigationController(session).start())

class NavigationController {
  // session.ui is generic over Channels; we cast once at construction so
  // every send/on/handle call below gets full type inference from the
  // shared registry.
  private ui: UIModule<Channels>
  private location: LocationManager
  private compass: CompassManager
  private display: DisplayManager
  private navigation: NavigationManager
  private storage: SimpleStorageManager
  private places: PlacesManager

  private unsubs: Array<() => void> = []
  private started = false

  // Canonical state (mirrored to UI via session.ui.send)
  private coords: Coords | null = null
  private heading: number | null = null
  private trip: TripState = {...}
  private activePivot: Pivot | null = null
  private upcomingPivot: Pivot | null = null
  private log: LogEntry[] = []
  private devSettings: DevSettings = {...}

  constructor(private readonly session: MiniappSession) { /* construct managers */ }

  start(): void {
    if (this.started) return
    this.started = true

    this.wireSensorSubscriptions()      // location, heading, navigation events
    this.wireUIHandlers()                // session.ui.handle(...) registrations
    this.wireUIBroadcasts()              // session.ui.on(...) for UI actions
    this.wireGlassesHUD()                // re-renders glasses display on state changes
    this.primeNavigationPermission()     // eager Google Nav T&C
    this.seedInitialFix()                // location.getOnce() to seed

    this.session.onBeforeDisconnect(() => this.dispose())
  }

  // ──────────────────────────────────────────────────────────────
  private wireSensorSubscriptions(): void {
    this.unsubs.push(this.session.location.onUpdate((d) => {
      this.coords = {lat: d.lat, lng: d.lng, accuracy: d.accuracy, ts: d.timestamp ?? Date.now()}
      this.ui.send("nav:coords", this.coords)
    }))
    this.unsubs.push(this.session.navigation.onPivot(() => {
      this.activePivot = this.session.navigation.getActivePivot()
      this.upcomingPivot = this.session.navigation.getUpcomingPivot()
      this.ui.send("nav:pivots", {active: this.activePivot, upcoming: this.upcomingPivot})
    }))
    // ... compass with 10Hz throttle, navigation onUpdate / onRoute, etc.
  }

  private wireUIHandlers(): void {
    this.ui.handle("nav:compute-route", (opts) => this.session.navigation.computeRoute(opts))
    this.ui.handle("nav:request-permission", () => this.session.navigation.requestPermission())
    this.ui.handle("nav:get-state", () => this.buildSnapshot())

    this.ui.handle("places:autocomplete", ({query, near}, {signal}) =>
      this.places.autocomplete(query, near, signal))
    this.ui.handle("places:details", ({placeId}) => this.places.details(placeId))

    this.ui.handle("storage:list-saved", () => this.storage.getAllSavedPlaces())
    this.ui.handle("storage:add-saved", (p) => this.storage.addSavedPlace(p))
    // ... rest of storage / recent
  }

  private wireUIBroadcasts(): void {
    this.ui.on("nav:start", async (opts) => { /* setState, then session.navigation.start(opts) */ })
    this.ui.on("nav:stop", () => { /* setState, session.navigation.stop() */ })
    this.ui.on("nav:deviate", () => { /* call session.navigation.dev */ })
    this.ui.on("nav:set-destination", (place) => { /* mostly informational; trip starts on nav:start */ })
    this.ui.on("nav:set-dev-settings", (partial) => { this.devSettings = {...this.devSettings, ...partial} })

    // Mid-trip hydration: when a fresh WebView opens, push the full snapshot.
    this.ui.onOpen(() => this.ui.send("nav:snapshot", this.buildSnapshot()))
  }

  private wireGlassesHUD(): void {
    // The HUD logic from NavigationPage:240-309 lives here.
    // Triggered any time trip/status/activePivot/upcomingPivot/coords change.
    // Calls this.display.showText(...) — no React, no re-render concerns.
  }

  private buildSnapshot(): NavSnapshot { /* coords + heading + trip + pivots + log + devSettings */ }
  private dispose(): void { /* unsub all, stop trip, clear display, drop state */ }
}
```

### What the User class becomes

Deleted. Its responsibilities split:
- **Reactive state** (`coords`, `heading`, `mapsReady`) → Zustand store fed by channels.
- **Imperative managers** (`navigation.*`, `display.*`, `storage.*`) → background controller. UI doesn't import managers.
- **`mapsReady`** → stays UI-side; tracked by `googleMaps.ts` on the UI side.
- **Sensor → state plumbing** → moves into `NavigationController.wireSensorSubscriptions`.

`useUser` and `client/hooks/useUser.ts` are deleted. The `client/` folder is deleted entirely (its files moved to `background/`).

`build.ts` rewritten to mirror `sdk/example-miniapp/build.ts`:

- Two `Bun.build` calls — `src/background/index.ts` → IIFE; `src/ui/index.html` → DOM bundle with Tailwind.
- `EXPO_PUBLIC_GOOGLE_NAV_API_KEY` inlined into UI bundle (Maps script needs it); the background bundle doesn't need it (Places REST uses `EXPO_PUBLIC_GOOGLE_PLACES_API_KEY` which background reads via `process.env` at build time — `define` inlines that too).

## Tests

### SDK RPC tests (`mobile/modules/miniapp/src/modules/ui.test.ts`)

New cases:
1. `handle` registers; `request` resolves with the handler's return value
2. Handler throws → `request` rejects with `Error` whose `name === "MentraRpcError"`
3. Handler throws with `Object.assign(new Error(""), {cause: {code: "X"}})` → caller sees `err.cause.code === "X"`
4. Double-registration of `handle` on the same channel throws synchronously
5. `request` before `mentra.ready` buffers and fires after open
6. `AbortSignal` from caller → `UI_CANCEL` fires; handler's `ctx.signal` aborts; caller's promise rejects with `AbortError`
7. Two concurrent `request`s to the same channel get separate request IDs and separate replies
8. Timeout → `UI_CANCEL` fires; promise rejects with `MentraRpcTimeoutError`
9. Handler returning before cancel → reply still resolves caller's promise
10. UI unmount mid-call (simulated by listener removal) → no crash; the next reply is silently dropped

### Navigation tests (`sdk/Navigation/src/test/`)

Existing tests in `src/test/navigation/*` test `NavigationManager` directly. They stay valid — the manager just imports from `background/managers/` now. Update import paths only.

No new tests for the controller layer in this PR; verification is manual via the device. A controller test harness with a mock session is a worthwhile follow-up but out of scope here.

- Start trip → glasses HUD shows the welcome message → updates to "Turn left in 200m" on approach → "Onto X" mid-turn → "You have arrived" on arrival.

## Out of scope

- Streaming RPC primitive.
- Bidirectional RPC (background calling UI).
- Vanilla (non-React) example template.
- Code-mod or migration tool for existing single-bundle mini apps to two-layer.
- A `MiniappController` SDK base class. The example uses plain classes; Navigation will too.
- Multi-app shared controllers.
- HMR-aware hot-swappable controllers.

## Decisions, locked

- **Trip state lives in background, fully.** Closing the WebView mid-trip never loses state.
- **Single `Channels` registry**, with `Rpc<Req, Res>` as the discriminant for RPC entries.
- **Wire protocol grows by one optional envelope field (`requestId`) + one new envelope type (`UI_CANCEL`).** No payload pollution.
- **One handler per RPC channel.** Double-register throws synchronously.
- **No default timeout.** Optional `{timeout}` per call.
- **Plain `Error` for failures**, with `err.name === "MentraRpcError"` as the sentinel and `err.cause?.code` for programmatic handling.
- **`useRpc` returns a callable with `.abort()`** for keystroke cancel-previous patterns; auto-aborts on unmount.
- **Handler's second arg `ctx: {signal}` is optional.** 1-arg signature works.
- **Refactor TesterController in the example as part of this PR.** Worked reference, smoke-tests the helper.
- **All in `mentra-miniapp-sdk-2` branch.** Not split across PRs.

## What this spec doesn't decide

- The exact shape of `NavigationController`'s internal helpers (private methods for HUD layout, log appending, etc.) — write to taste during implementation.
- Whether the Navigation tests grow a controller harness. Probably yes as a follow-up, not blocking this PR.
- The exact `sdkVersion` / `minHostVersion` values in `miniapp.json` — pull whatever's current at implementation time.
