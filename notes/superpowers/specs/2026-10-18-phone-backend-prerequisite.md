# Fresh phone backend prerequisite

An Android routine declaring the existing phone `backend-connectivity` capability must have a fresh, target-specific observation before executable admission and native app setup. Structural host/lane selection and host-only preparation may precede that observation. A static installed capability or host internet connection is insufficient. The selected APK remains the only authority for the backend origin. A shell default-network/TCP witness proves neither the app's HTTP/CDN route nor future connectivity; `appRouteVerified` remains false and product assertions remain unchanged.

Use only the existing typed resource offers, qualification target delivery, host-row `resourceReservations` CAS, local resource rows, sealed reader journal, native closure receipts and normal cancellation/return transport. No resource registry, endpoint, credential store or monitor service is added.

1. Existing host-row recorder provisional claims serialize preparation on Android lanes offering phone `backend-connectivity`, including offline routines sharing that physical lane. A retained other-request same-lane claim waits before request staging or dependency acquisition, regardless of available recorder bytes; other lanes retain ordinary capacity sharing. The existing request CAS selects one immutable host/lane and preparing delivery, preserving the exact app archive/receipt/source, routine source, request and original deadline. These structural claims never authorize native app setup. Lost responses retain the same original claims for observation/adoption; no second concurrent candidate or cross-collection transaction is introduced.
2. The host completes exact host-only source/tool/fixture preparation and retains its original result, then verifies the pinned APK configuration before obtaining device custody. A missing or unsupported target is unknown. Controller service URLs, channel labels and fixtures cannot supply a replacement target.
3. A capability-scoped existing resource check acquires the exact phone row without inventing a lane owner. The existing Core reservation intent has a narrow prerequisite purpose for that original target, current controller and phone. Its raw-phone claim uses the same host-row CAS. Probe acquisition rejects retained ordinary run claims for that lane; ordinary admission rejects probe claims before staging a candidate. All preparation sharing a backend-capable Android phone retains its existing recorder byte claim on that same host row before the existing request CAS stages a candidate. The request CAS selects one immutable host/lane; a provisional claim alone never authorizes execution. Lost transport preserves the original intent or byte claim for observation/adoption, without another acquisition for that original target. No cross-collection transaction or database-specific fallback is required. Multiple provisional claims observed on distinct hosts fail closed and retain custody; the request CAS still prevents a second executable candidate.
4. The check seals its exact reader roster, command/input digest, tool and phone before dispatch. One bounded read observes boot identity, default-network state and TCP reachability to the verified hostname. Cancellation, source/controller change, target replacement or expiry cannot authorize a child or publish positive health.
5. Capability failure is separate from physical idle. A parsed negative result may release read custody after every original reader closes; an unknown child retains custody until original closure. Release appends a real resource-check release event and existing Core return receipt. It never synthesizes a lane release, physical restoration or old idle-contract pass. Original unknown outcomes remain immutable even if later transport settlement permits release.
6. Core executable admission and the local pre-allocation check consume only qualified, released, current-source/controller/phone/build/target observations within 120 seconds. Resource generation invalidates prior health after another owner. Negative or expired health withdraws backend eligibility only; offline routines, safe cleanup and other resources remain independent. The execution-time selected-app-process guard still measures before credentials/actions.

For unbound work, accepted API70 hosts advertise support for a candidate prerequisite on the existing request. One pending candidate preserves the original job, source, APK, definition and deadline before recorder, dependency or execution admission. Its APK-derived backend target is frozen on the first exact acquisition intent without changing the initial target digest. A candidate is completed only after raw host work/artifact cleanup, every original reader, local check release, and Core phone-return acknowledgement settle. A negative can then select another host/lane for the same job. Unknown work or lost acknowledgements retain the original pending candidate; existing bound requests are never retargeted.

A negative candidate result is historical settlement after its original observation, raw reader closure, host-work closure and Core return acknowledgment are authenticated. Its observation does not expire merely because artifact cleanup or report delivery takes more than 120 seconds. Core still requires a fresh authenticated host envelope, exact accepted source/controller, current unowned returned subject generation and retained original check/claim/return identity. Only a positive result can select executable resources, and that result retains its 120-second freshness bound. Cancellation or original deadline expiry permits historical settlement only, never another candidate or execution.

The original candidate host can read its exact completed candidate history through the existing authenticated preparation metadata GET, including after another host is selected or the request terminates. Access is bounded to 20 parsed entries and validates original job, selection, source, definition, target digest and deadline. This confirms Core consumed the local settlement before a generic idle check changes the returned subject. Missing, changed or lost responses retain the local fence; broad target-list absence is not an acknowledgment. Historical metadata does not grant routine-source, prepared-input or native reader authority.

At most 20 candidate attempts fit under the original deadline. Negative or unknown same-host/lane attempts cannot be renewed. Only the immediately preceding returned positive may receive a distinct same-phone candidate after genuine 120-second expiry; immutable predecessor identities, source/controller, absence of local run work, and the finite history are checked on both sides. Fresh health is required before final binding and executable admission. If expiry follows provisional recorder/dependency claims, a request-row pending fence first retains those exact receipts, blocking bind/staging. Fresh authenticated idle/storage and unowned dependency observations plus original authority CAS/readback return only those never-executed claims; a lost response retains the pending receipts until exact readback. Only then is the renewed candidate exposed. A negative renewal can choose an alternate after its own authentic closure/return; cancellation during claim return permits cleanup but no renewed reader or alternate. No deadline, failed outcome, or prior proof timestamp is reset.

Once bound, the existing preparing-origin check remains one immutable attempt. Slow host-only preparation precedes its owned observation. It uses the original native child-close timestamp; later delivery cannot renew it. Genuine candidate positive age-out after binding may require that distinct ordinary preparing-origin check, while old bound or failed preparing attempts keep their strict original identity and deadline.
Existing local operator and candidate admission uses the same prerequisite path without inventing a fleet preparing row. The current authenticated host snapshot projects at most 30 immutable `localPrerequisites` targets within 256 KiB. Each contains the original local request, operation, input/definition digest, deadline, accepted Framework binding and controller. Operator descriptors originate from authenticated installed admission; candidate installer/completion hashes are controller assertions, while Core independently validates the actual accepted work, current attempt, exact-source independent review, build and enrolled definition. An existing accepted completion retry may extend only its exact original local request to its recorded retry deadline; arbitrary renewal is refused. Any Core request row with that identity, including a terminal tombstone, excludes local pre-admission.

Local qualification can run under an explicitly requested paused/authoring idle lane without changing its mode. Its phone claim blocks every same-lane run/recorder claim, using the existing host-row CAS. Source, cancellation, deadline or reporter changes withdraw native eligibility but do not remove a committed original claim. The existing observe route recovers only that original claim after a lost answer; authentic resource-check release and return ACK remain valid after target withdrawal. Historical descriptor retention never grants current reader authority.

Core accepting-source deployment precedes matching API70 candidate-host activation after paired review and the required current-consumer proof. Existing API61 preparing work retains its prior contract. Source tests establish claim and cancellation behavior, not live phone readiness, database deployment compatibility, an original network cause, or an app HTTP/CDN route guarantee.

Required offline tests cover probe/run claim races in both directions, two-request same-phone progression (including offline requests and slow preparation), response loss/restart, exact APK/target/phone/source/generation mismatches, future/expired/unknown health, cancellation during verification/claim/read/export, missing or extra roster members, late results after expiry, and negative health releasing read custody without changing idle/repair behavior. A source PR or CPU fixture is not device qualification or proof of any original network cause.
