# Cloud V2 - Handoff (PR #3272)

PR: https://github.com/Mentra-Community/MentraOS/pull/3272

**What it is:** Cloud V2 console/admin/portal, plus a miniapp registry (signed publish), plus preinstall to mobile auto-update. Also includes WorkOS PKCE console/CLI login, the `oemId` to `tenantId` rename, runtime reconnect fixes, and CI/CD for dev/staging/prod.

## Environments and CI/CD (now wired)

Each environment is its own Porter app, its own Doppler config, and its own database. Pushing to the matching branch auto-deploys it (the image is tagged with the git SHA via Porter):

| Env | Branch (auto-deploy) | Porter app | Backend | DB (Doppler config) |
|---|---|---|---|---|
| Dev | `dev` | `cloud-dev` | `core.dev.us-west-2...` | `cloud-v2 / dev_aws` |
| Staging | `staging` | `cloud-staging` | `core.staging.us-west-2...` | `cloud-v2 / staging` |
| Prod | `main` | `cloud-prod` | `core.mentraglass.com` | `cloud-v2 / prod` |

Debug is a separate, older app. Each env reads its own secrets and DB from its own Doppler config, so the environments are isolated.

Caveat: the Dev server is currently running my branch, not the `dev` branch. This resolves once I merge to `dev` and `dev` auto-deploys.

## Auth: WorkOS (consoles/CLI) vs Supabase (app)

- Dev Console, Admin, Portal, and the CLI use WorkOS (AuthKit plus PKCE). We use WorkOS because it gives us organizations, org invites and roles, and CLI/SSO auth out of the box, so we do not have to build all of that ourselves.
- The MentraOS app (mobile/glasses) still uses Supabase, unchanged. The cloud-v2 token exchange verifies the Supabase session and mints the runtime token.

So: WorkOS for the developer and B2B surfaces, Supabase for the consumer app.

## Captions and performance (priority 1)

- Captions reconnect bug, FIXED today (`12c754e28`, follow-up to `832e08b16`). Captions died on reconnect because the runtime only superseded the old session when `authSessionId` matched, but reconnects get a fresh token. It now supersedes by user, so a reconnect takes over the subscription cleanly. Verify on device.
- Still open: captions lag, or "feels slow", when backgrounded. Captions run as a local miniapp on a single serial JS queue. Screen-off throttling (iOS suspend, Android Doze) makes transcripts pile up and flood on resume. BGCAP telemetry (`#3273`) was added to diagnose the JS-thread suspension. The fix has not landed yet.

## CLI: build and publish a miniapp to the registry

`@mentra/cli` (bin `mentra`, at `cloud-v2/packages/cli`). Until it is on npm, run it via the env wrappers from `cloud-v2/`. Each wrapper points the CLI at that env's Core, console, and DB:

- `mentra:dev` is Dev, `mentra:staging` is Staging, `mentra:prod` is Prod, `mentra:local` is local.

```bash
# from cloud-v2/  (targets Dev)
bun run mentra:dev login                                   # sign in (WorkOS) + register signing key
bun run mentra:dev org init                                # one-time: org + package prefix
bun run mentra:dev miniapps create com.yourorg.weather     # reserve a package name
bun run mentra:dev publish --cwd ~/code/weather-miniapp    # build + pack + SIGN + upload a release
bun run mentra:dev releases submit com.yourorg.weather <releaseId>   # submit for review
# admin then approves/publishes (Admin console or admin API)
bun run mentra:dev admin preinstall publish -r com.yourorg.weather@0.1.0 -e dev   # phones auto-install/update
```

- Local dev loop: `bun run mentra:dev dev --cwd ~/code/weather-miniapp`
- Two CLIs: `mentra-miniapp` creates and builds miniapps; `@mentra/cli` wraps it and adds login, publish, and registry.
